# 논의방 기능 기획 초안

> 상태: 아이디어 정리 단계  
> 작성일: 2026-08-28  
> 목적: 주말 설계·구현 논의를 재개하기 위한 기준 문서

## 1. 목표

AI Task Router에 사용자와 여러 AI가 하나의 안건을 자유롭게 논의하는 채팅방을 추가한다.

겉으로는 일반적인 단체 채팅방처럼 동작하지만, 실제 논의의 단일 기준은 별도 원본 논의
문서다. 채팅은 사람이 빠르게 읽기 위한 요약 화면이고, AI는 채팅 요약이 아니라 최신 원본
문서를 읽고 판단한다.

기본 참여자는 다음 세 명이다.

- 사용자
- Claude
- Codex

사용자는 논의 중 AI 참여자를 추가하거나 강퇴할 수 있다.

## 2. 핵심 원칙

### 자유로운 채팅

- 사용자는 일반 메신저처럼 자연어로 대화한다.
- `채택`, `반박`, `동의` 같은 의사결정 버튼을 두지 않는다.
- 사용자가 "그건 이렇게 하자", "이걸로 결정", "이건 제외"처럼 방향을 말하면 Router가
  이를 원본 문서의 사용자 결정으로 반영한다.
- 의미가 애매한 경우에만 사용자에게 결정인지 의견인지 확인한다.

### 원본 문서가 단일 기준

- AI는 답변 전에 최신 원본 논의 문서를 읽는다.
- AI의 상세 의견, 근거, 반박, 수용 내용은 원본 문서에 먼저 기록한다.
- 채팅방에는 결론과 핵심 근거만 짧게 공유한다.
- 다음 AI는 앞선 AI의 채팅 요약이 아니라 갱신된 원본 문서를 기준으로 의견을 낸다.
- 관련 코드·파일·검증 결과는 원본 문서에 경로와 근거를 남긴다.

### 객관적인 협의

- AI는 사용자 의견을 존중하지만 무조건 동의하지 않는다.
- 기존 구현량과 매몰비용만으로 결론을 정하지 않는다.
- 기술적 사실, 추정, 추천과 사용자 결정을 구분한다.
- 합리적인 반박과 새 근거는 수용하고 기존 의견을 수정할 수 있어야 한다.
- 반대로 충분한 근거 없이 빠르게 동조하는 것도 금지한다.

### 무한 논의 방지

- 동일한 주장과 근거를 반복하지 않는다.
- 재반박은 새로운 사실, 코드, 측정값 또는 새로운 논리가 있을 때만 허용한다.
- 새 근거 없이 입장이 유지되면 반복 답변 대신 `입장 유지`로 문서에 표시한다.
- 합의되지 않는 쟁점은 사용자 조율이 필요한 항목으로 올린다.
- 사용자가 조율 방향을 제시하면 각 AI는 그 방향 안에서 현실적인 최종안을 제안한다.
- 최종 결정권은 사용자에게 있다.

## 3. 논의 시작 흐름

1. 사용자가 Codex 또는 Claude 채팅에서 자연어로 논의 시작을 요청한다.
2. 전용 스킬이 다음 내용을 구조화한다.
   - 논의 제목
   - 배경과 목적
   - 핵심 질문과 현재 쟁점
   - 확인된 사실과 미확인 사항
   - 관련 프로젝트 저장소
   - 기본 참여자
   - 제외 범위
3. Router에 논의방과 원본 논의 문서를 생성한다.
4. 참여 AI들은 원본 문서를 읽은 뒤 각자의 상세 의견을 기록하고 채팅에 요약을 게시한다.

논의 시작 스킬은 기존 Task 실행 스킬과 분리한다. 논의방 생성은 구현 Task를 만들거나 코드를
수정하는 작업이 아니다.

## 4. 관련 프로젝트 저장소

- 논의 시작 시 관련 프로젝트 저장소 기록은 필수다.
- AI는 등록된 저장소와 명시된 참고 문서만 기본 조사 범위로 사용한다.
- 등록되지 않은 다른 저장소를 임의로 전체 조사하지 않는다.
- 논의 중 필요한 저장소가 발견되면 사용자가 추가하거나, AI가 추가 필요성을 요청할 수 있다.
- 저장소가 추가되면 새 문서를 만들지 않고 기존 원본 논의 문서의 관련 저장소 목록을 갱신한다.
- 저장소가 추가된 시점과 이유를 변경 이력에 남긴다.

## 5. 원본 논의 문서 구조

원본 문서는 최소한 다음 정보를 가진다.

- 논의 ID와 제목
- 상태: 진행 중 / 조율 중 / 종료
- 생성·최종 갱신 시각과 문서 버전
- 현재 참여자와 참여 이력
- 관련 프로젝트 저장소와 참고 문서
- 논의 배경과 목표
- 확인된 사실
- 사용자 의견
- 사용자 결정
- 합의된 내용
- 미결정 쟁점
- AI별 상세 의견과 근거
- 철회·정정된 의견
- 최종 결론과 후속 작업
- 변경 이력

AI의 상세 의견은 상대가 쓴 내용을 수정하지 않고 자신의 새 항목으로 추가한다. 상단의 확인된
사실·합의·미결정 요약은 근거가 추가되거나 사용자 결정이 나올 때 갱신한다.

## 6. 사용자 의견 기록 방식

사용자 발언은 `사용자 의견`과 `사용자 결정`을 분리한다.

### 사용자 의견

- 아직 확정하지 않은 선호, 문제 제기, 반박, 조건부 방향을 기록한다.
- Router가 의미를 짧게 구조화하되 원래 취지를 바꾸지 않는다.
- 발언 시각과 채팅 메시지 ID를 연결해 원문을 추적할 수 있게 한다.
- 긴 채팅 원문 전체를 원본 논의 문서에 반복 복사하지 않는다.

### 사용자 결정

- 사용자가 명확하게 최종 방향을 말한 경우에만 기록한다.
- AI가 사용자의 침묵, 질문 또는 단순 동의를 최종 결정으로 추정하지 않는다.
- 애매하면 의견으로만 두고 사용자에게 확인한다.
- 사용자가 결정을 취소하거나 바꾸면 기존 기록을 몰래 덮어쓰지 않고 `정정됨`으로 표시한 뒤
  새 결정을 추가한다.

예시:

```text
사용자 의견
- 미러 구조를 유지한다면 남은 수집도 기존 계획대로 진행하는 편을 선호한다.
- 근거 메시지: #184, 10:02

사용자 결정
- 아직 없음.
```

## 7. AI 발언 처리 흐름

AI 한 명의 발언은 다음 순서를 반드시 따른다.

1. 원본 논의 문서의 최신 버전을 읽는다.
2. 확인된 사실, 사용자 의견·결정, 다른 AI의 상세 근거를 검토한다.
3. 자신의 상세 의견을 원본 문서에 기록한다.
4. 문서 버전과 갱신 성공을 확인한다.
5. 채팅방에는 결론과 핵심 근거만 요약해 게시한다.

동시에 여러 AI가 작성할 때는 문서 버전 충돌을 감지해야 한다. 작성 직전 기준 버전과 현재
버전이 다르면 최신 문서를 다시 읽고 의견을 조정한 뒤 기록한다.

## 8. 채팅방 UX

### 기본 화면

- 중앙: 사용자와 AI들의 자유로운 요약 채팅
- 상단: 논의 제목, 진행 상태, 참여자, 관련 저장소
- 보조 영역: 현재 합의 내용과 남은 쟁점의 자동 요약

일반적인 채팅 경험을 유지하고 회의 관리 UI를 전면에 내세우지 않는다.

### 메시지 표시

- AI 메시지는 기본적으로 결론과 핵심 근거 3~5줄 정도만 표시한다.
- 상세 분석은 `상세 의견 보기`를 통해 원본 문서의 해당 항목을 연다.
- 코드·문서 근거가 있으면 메시지 아래에 작은 참고 링크를 표시한다.
- 의견이 바뀐 경우 이전 발언을 삭제하지 않고 정정 또는 수용 사실을 보여준다.

### 참여자 관리

- 기본 참여자는 사용자, Claude, Codex다.
- 사용자는 논의 중 AI를 추가하거나 강퇴할 수 있다.
- 새 AI에게 전체 채팅 로그를 그대로 전달하지 않는다. 최신 원본 문서와 등록된 저장소만
  전달한다.
- AI가 강퇴돼도 기존 의견과 참여 이력은 원본 문서에 남긴다.

## 9. 논의 종료

- 논의 종료는 사용자가 직접 실행한다.
- 종료 전 Router가 다음 내용을 원본 문서에 정리한다.
  - 최종 사용자 결정
  - 합의된 내용
  - 채택하지 않은 안과 이유
  - 남은 위험과 미확인 사항
  - 후속 작업
- 합의점에 도달하지 못했으면 사용자가 조율 방향을 제시할 수 있다.
- 각 AI는 사용자가 제시한 방향에 최대한 맞으면서도 기술적으로 성립하는 최종안을 제안한다.
- 사용자가 최종 결론을 확정하고 종료 버튼을 누르면 문서를 종료 상태로 바꾼다.
- 종료 후 변경이 필요하면 종료 문서를 고치기보다 연결된 새 논의를 시작하는 방식을 우선한다.

## 10. 기존 Task 기능과의 관계

- 논의방은 코드 구현·분석·리뷰 Task와 별도 도메인이다.
- 논의 중에는 프로젝트 파일 수정, 테스트 실행, 브랜치 변경, 커밋 또는 푸시를 자동 수행하지
  않는다.
- 논의 결과 후속 구현이 필요하면 사용자가 별도로 Task를 생성한다.
- 종료 문서의 확정사항을 새 Task의 입력으로 변환하는 기능은 후속 기능으로 검토할 수 있다.

## 11. 주말 설계 시 먼저 결정할 항목

1. 논의방과 원본 문서의 영속화 형식 및 저장 위치
2. 문서 버전 관리와 동시 작성 충돌 처리 방식
3. 사용자 발언을 의견·결정으로 분류하는 기준
4. Codex·Claude 외 AI 참가자 어댑터 구조
5. AI별 상세 기록 후 채팅 요약을 게시하는 실행 순서
6. 반복 반박을 감지하는 기준과 사용자 조율 전환 조건
7. 종료 문서 생성과 종료 후 재논의 연결 방식
8. 기존 MCP 서버에 필요한 논의방 도구와 전용 스킬의 경계

## 12. 현재 제외 범위

- 논의 결과에 따른 자동 코드 수정
- AI가 사용자 대신 최종 결론을 확정하는 기능
- `채택`·`반박`·`동의` 버튼 중심의 회의 관리 UX
- 채팅 내용만으로 다음 AI가 판단하는 구조
- 등록되지 않은 저장소의 무제한 자동 조사
